# 问题修复 - 只回复新消息

## 问题描述

**之前的问题：**
- 启动机器人后，会把所有历史未读消息都回复一遍
- 包括启动前很久的旧消息
- 导致重复回复，用户体验不好

**期望效果：**
- 只回复启动后新发送的消息
- 忽略启动前的所有历史消息
- 从启动时刻开始监听

## 解决方案

### 实现原理

在机器人启动后，第一次获取消息时：
1. 读取所有当前的历史消息
2. 将这些消息标记为"已处理"（加入去重列表）
3. 不返回这些消息，不触发回复
4. 之后只返回新收到的消息

### 代码修改

在 `src/core/wechat_client.py` 中：

```python
def __init__(self):
    self.initialized = False  # 标记是否已初始化

def get_latest_messages(self, who: str = None):
    # 第一次调用时，清空所有历史消息
    if not self.initialized:
        log.info("首次启动，正在清空历史消息...")
        # 读取但不返回历史消息
        self._get_messages_wxauto(who)
        self.initialized = True
        log.info("历史消息已清空，开始监听新消息")
        return []  # 第一次不返回任何消息

    # 之后正常返回新消息
    return self._get_messages_wxauto(who)
```

## 技术细节

### 消息去重机制

使用 `self.last_messages` 字典存储已处理的消息：
```python
msg_id = f"{sender}_{time_str}_{content}"
if msg_id not in self.last_messages:
    self.last_messages[msg_id] = True
    new_messages.append(msg_dict)
```

### 初始化标记

使用 `self.initialized` 标记：
- `False`：首次调用，清空历史
- `True`：正常运行，返回新消息

## 注意事项

### 1. 启动时机

- 建议在打开聊天窗口后再启动机器人
- 这样可以确保历史消息被正确读取和清空

### 2. 重启机器人

- 每次重启机器人，都会重新清空历史消息
- 不会回复重启前的消息

### 3. 消息延迟

- 如果消息发送和机器人启动几乎同时
- 可能会被当作历史消息忽略
- 建议启动后等待几秒再发消息测试

## 常见问题

**Q: 启动后第一条消息没有回复？**
A:
- 检查是否在清空历史消息时发送的
- 建议启动后等待3-5秒再发消息
- 查看日志确认是否已完成初始化

**Q: 还是会回复历史消息？**
A:
- 检查日志是否显示"历史消息已清空"
- 确认使用的是最新代码
- 尝试重启机器人

**Q: 如何确认历史消息已清空？**
A: 查看日志文件 `logs/ailive.log`，应该有：
```
[INFO] 首次启动，正在清空历史消息...
[INFO] 历史消息已清空，开始监听新消息
```
