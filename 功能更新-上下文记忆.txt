# 功能更新 - 持久化上下文记忆

## ✅ 已完成的改进

### 1. 自动加载历史对话

**之前的问题：**
- 每次启动机器人，对话都从零开始
- 机器人不记得之前说过的话
- 用户需要重新介绍自己

**现在的功能：**
- ✅ 首次收到用户消息时，自动加载历史对话
- ✅ 从上次对话的地方继续
- ✅ 机器人记得之前的对话内容

### 2. 自动保存对话

**保存机制：**
- 每5条消息自动保存一次
- 保存到 `data/conversations/` 目录
- 每个用户一个文件：`用户名_context.json`

**优势：**
- 不需要手动保存
- 程序崩溃也不会丢失太多数据
- 重启程序后自动恢复

### 3. 滑动窗口机制

**工作原理：**
- 保留最近20条消息（可配置）
- 超过限制自动删除最旧的消息
- 平衡记忆长度和API费用

**配置方法：**
```yaml
# config/config.yaml
ai:
  max_context_messages: 20  # 调整这个数值
```

## 使用示例

### 场景1：记住用户信息

**第一天对话：**
```

```

**下午（重启机器人后）：**
```

AI: Python学习遇到问题了吗？说说看~
```

## 文件存储

对话历史保存位置：
```
data/conversations/
├── 小明_context.json
├── 小红_context.json
└── ...
```

每个文件包含：
- 消息内容
- 角色（user/assistant）
- 时间戳

## 清除历史

如果需要清除某个用户的对话历史：

**方法1：删除文件**
```
删除 data/conversations/用户名_context.json
```

**方法2：清空目录**
```
删除 data/conversations/ 目录下的所有文件
```

## 配置说明

### 调整记忆长度

在 `config/config.yaml` 中：
```yaml
ai:
  max_context_messages: 20  # 保留的最大消息数
```

**推荐值：**
- 10条：短期记忆，费用低
- 20条：中期记忆，平衡（推荐）
- 30-50条：长期记忆，费用高

**注意：**
- 数值越大，记忆越长
- 但每次API调用费用也越高
- 建议根据实际需求调整

### 调整保存频率

在 `src/utils/context_manager.py` 中：
```python
self.auto_save_interval = 5  # 每5条消息保存一次
```

可以修改为：
- 3：更频繁保存，更安全
- 10：较少保存，减少IO

## 技术细节

### 实现原理

1. **首次消息触发加载**
   - 检测到新用户
   - 查找对应的历史文件
   - 加载最近N条消息

2. **滑动窗口**
   - 使用 `deque` 数据结构
   - 自动维护固定长度
   - 新消息进，旧消息出

3. **自动保存**
   - 计数器跟踪消息数
   - 达到阈值触发保存
   - 异步写入文件

### 性能优化

- ✅ 使用JSON格式，读写快速
- ✅ 只加载需要的消息
- ✅ 异常处理，不影响主流程
- ✅ 文件名安全处理

## 注意事项

### 1. 隐私保护

- 对话历史保存在本地
- 不会上传到云端
- 注意保护 `data/conversations/` 目录
- 建议定期备份或清理

### 2. 存储空间

- 每个用户约几KB到几十KB
- 20条消息约5-10KB
- 定期清理不需要的历史

### 3. API费用

- 上下文越长，费用越高
- 建议监控API使用量
- 根据预算调整 `max_context_messages`
